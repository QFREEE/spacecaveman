Publish NYC Status

Start with a four-action manual button. Add automations after it works.

Repository-only guide. This page is excluded from production. Reports go to the protected viewer. The public homepage still shows Unknown. This guide contains no credentials and makes no API requests.

1. Have your write credential ready

On your computer, open the private .presence-private/iphone-setup.txt file. Transfer the write credential privately to your phone. Use it only in Shortcuts. The separate read credential belongs in the private viewer.

Never put either credential in a URL, this guide, a screenshot, or a shared shortcut. Anyone who can inspect a populated shortcut can use its credential. Reusable shortcuts may sync through iCloud.

2. Easy start: four actions

In Shortcuts → Shortcuts → +, name it Update NYC Status. Add:

  1. Date → Current Date.
  2. Format Date → ISO 8601, including time and time zone.
  3. URL → https://spacecaveman-presence-trial.spacecaveman.workers.dev/api/presence
  4. Get Contents of URL → expand options, choose POST and JSON. Add Headers: Authorization = Bearer followed by your private write credential, and Content-Type = application/json.
    Add three Text fields to the JSON body
    KeyValue
    statusin_nyc if actually in NYC; otherwise not_in_nyc
    observed_atFormatted Date variable
    event_idThe same Formatted Date variable

Tap ▶. Success returns {"accepted":true}. Confirm the status and report time in the private viewer using your separate read credential.

Select the date variable; do not type “Formatted Date”. This simple single-phone recipe uses the fresh timestamp as its event ID. The API requires strictly newer timestamps and at least 10 seconds between reports. Never reuse a timestamp to make a new report.

To clear a report, change status to unknown and run again after 10 seconds. No coordinates are sent. The four-action button reports only the status you put in it; it does not detect your location.

Optional: reusable menu and Arrive/Leave automation

Build the reusable version

In Shortcuts → Shortcuts → +, name it Publish NYC Status. Add the actions below in order. Names can vary by iOS version; the original trial targets iOS 17.

  1. Add If: Shortcut Input has any value. Inside, use Set Variable to set ReportStatus to Shortcut Input.
  2. Inside Otherwise, add Choose from Menu with three items. Under each item, add a Text action with the corresponding code below. After End Menu, set ReportStatus to Menu Result. Then end the If block.
    Menu items and their Text values
    Menu itemText
    In NYCin_nyc
    Not in NYCnot_in_nyc
    Unknown / clear reportunknown
  3. Add Date, set to Current Date. Add Format Date, using that date, with format ISO 8601 including time and time zone. Rename its output ObservedAt. Do not type a date or append a literal Z to local time.
  4. Add two Random Number actions, each between 100000000 and 999999999. Add Text: insert the ObservedAt variable, a hyphen, the first random output, a hyphen, and the second random output. Rename this Text output EventID. Insert variable tokens rather than typing their names.
  5. Add URL with this exact address. Long-press to select and copy:

    https://spacecaveman-presence-trial.spacecaveman.workers.dev/api/presence

  6. Add Get Contents of URL using the URL action. Expand its options. Set Method → POST and Request Body → JSON.
  7. In Headers, set Authorization to Bearer followed by your private write credential. Keep the space after Bearer. Set Content-Type to application/json.
  8. Add exactly these three Text fields in the JSON body. Select variables for their values:
    JSON request body
    KeyValue variable
    statusReportStatus
    observed_atObservedAt
    event_idEventID
  9. Add Get Dictionary Value, key accepted, from the response. End with Stop and Output that value. An accepted report returns Boolean true. An HTTP, permission, or network error is a failure; do not treat a completed action as confirmation.

Do not add Get Current Location. The request must contain only the three explicit fields above. This recipe needs verification on your physical phone; it is not an installed or signed shortcut download.

3. Test a manual report first

  1. Run Publish NYC Status from Shortcuts. Choose your actual status. Resolve the legitimate network permissions.
  2. Confirm the output is true. Open the private viewer and enter the separate read credential. Confirm status and report time.
  3. Wait at least 10 seconds, run it again, and choose Unknown / clear report. The viewer should become Unknown.

Adding the shortcut to your Home Screen gives you a manual fallback. Reports expire after six hours; they do not promise availability to meet.

4. Attach arrival and departure

For each trigger, go to Shortcuts → Automation → +. Choose Arrive or Leave, the same location and circle, and Any time. Choose Run Immediately, or disable Ask Before Running if that is the displayed control.

  1. Add Text: in_nyc for Arrive, or not_in_nyc for Leave.
  2. Add Run Shortcut → Publish NYC Status. Expand it and explicitly set Input to the preceding Text output. This bypasses the manual menu.

A circular trigger is not an exact NYC city boundary. Inspect the circle before using the city label. Leaving home or one NYC station does not establish your city status. Use manual reports if the circle is unsuitable.

Test arrival and departure with the phone locked, then offline transitions, reboot, and a visit longer than six hours. Assume no automatic retry until tested. Do not renew an old report with a fresh timestamp. Personal automations themselves do not sync across devices.

If publishing fails

401 · Unauthorized
Check the Bearer space, write credential, expiry, and revocation. Never substitute the viewer's read credential.
400 / 415 · Request format
Use JSON, exactly three text fields, variable outputs, and ISO 8601 with a time zone. Check the phone clock.
409 · Conflict
Duplicate, older, or too-frequent report. Wait 10 seconds, check your actual current status, then make a fresh report. Do not replay an old arrival.
503 / network error
Publishing is unavailable. The previous report can remain visible only until its expiry. Check the private viewer after connectivity returns.

Revocation: on your computer, use the dedicated trial's private revoke.sql with the documented Wrangler command. Revocation clears the current report. Do not share a populated shortcut to obtain support.

Recipe checked against Apple's API actions, travel triggers, and automatic execution. Device testing is still required.
